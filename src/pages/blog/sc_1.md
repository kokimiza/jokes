## このテキスト群の使い方

情報処理安全確保支援士（SC）試験の事例問題を、**根拠を探す → 攻撃・不備の成立条件を説明する → 指定された形で答える** 手順で解けるようにする特製テキストである。試験合格と、資格の登録・継続手続は区別する。

用語の説明を読んだら、各章末の実問を解く。誤答を「知らない用語」で一括りにせず、知識・読解・答案のどこで失点したかを確認する。[第8章](/blog/sc_8)には、独自演習と記述70大問すべての対応表を置いた。

**改訂日：2026年11月2日。** 過去問の分析対象は、同日時点で公開済みの直近8年度、2018〜2025年度。2026年度の非公開問題を分析したものではない。出題確率の予測や、合格を保証する教材でもない。

## 1. 試験形式と過去問の読み替え

| 項目 | 2026年度SCでの学習上の整理 |
|---|---|
| 科目A-1 | 旧午前Ⅰに対応。30問・50分。免除の有無を確認する |
| 科目A-2 | 旧午前Ⅱに対応。25問・40分 |
| 科目B | 旧午後に対応。150分、4問から2問を選択する記述式 |
| 実施方式 | CBT。画面の問題・図表を参照し、キーボード等で解答する |
| 答案の制約 | 字数、語句、個数、記号、行番号など、各設問の指定に従う |

2023年春までは午後Ⅰ（3問から2問・90分）と午後Ⅱ（2問から1問・120分）、2023年秋からは午後（4問から2問・150分）に統合された。**旧午後Ⅰ・Ⅱを、そのまま現行の時間配分で解かない。** 古い問題は個別の読解練習に使い、統合後の問題で150分の選択・完答を練習する。

字数指定のある旧問を使った練習は有効だが、すべての記述が字数制限付きとは限らない。長さを埋めることより、問いに必要な主体・対象・条件・理由を過不足なく書く。

試験方式・科目名・時間等は[IPAのCBT移行案内](https://www.ipa.go.jp/shiken/2026/ap_koudo_sc-cbt.html)と[試験要綱](https://www.ipa.go.jp/shiken/syllabus/gaiyou.html)による。日程、申込み、操作方法は[公式の実施期間案内](https://www.ipa.go.jp/shiken/2026/ap_koudo_sc_kikan.html)を確認する。過年度の「春4月・秋10月」をそのまま現在の予定として使わない。

### 出題から読み取ったこと

以下は筆者の分析であり、IPAが公表した分野別頻度や配点ではない。複合問題には複数の分野が含まれるので、大問を一つの用語だけで分類しない。

| 読み取れること | 比較する実問 | 学習に反映すること |
|---|---|---|
| Webはコード・データ・画面遷移をつないで問われる | 2018春Ⅱ問2、2022春Ⅰ問1、2023春Ⅰ問1、2025秋問1 | SQL構文、認可条件、共有変数、CSPの許可元まで読む |
| 認証は方式名より、検証対象と鍵の所在が重要 | 2019春Ⅰ問2・問3、2022春Ⅱ問2、2023秋問3、2025秋問2 | 署名する主体、宛先・要求との結び付き、鍵の移送を図示 |
| 通信経路の変更が、許可・監視の条件を変える | 2018春Ⅰ問2、2021春Ⅰ問2、2023春Ⅰ問3、2025秋問3 | 接続前後・移行前後で経路を分け、装置自身の通信も確認 |
| 調査にはログの項目・時刻・観測範囲の理解が要る | 2018秋Ⅱ問2、2019秋Ⅰ問3、2022秋Ⅱ問2、2024秋問1 | 事実と仮説を分け、何の記録で何を確認するかを書く |
| 管理も技術・業務条件と結び付く | 2019秋Ⅱ問2、2023秋問4、2025春問1・問2・問4、2025秋問4 | リスクを具体化し、既存対策、復旧、実施・承認の主体を示す |
| 古い問題にも今の理解を支える基礎がある | 2018春Ⅰ問1・秋Ⅰ問1、2020年10月Ⅰ問2 | メモリ保護、証明書、メールの暗号化等を補う |

ここで「春Ⅰ」は旧午後Ⅰ、「春Ⅱ」は旧午後Ⅱの略。例えばCSPは2021年秋午後Ⅱ問1にも登場する。「新しい用語だから直近だけ見ればよい」という扱いはしない。

## 3. 8章の学習順序

| 章 | テーマ | 読後に実行すること |
|---|---|---|
| [2](/blog/sc_2) | Webアプリ・API・セキュアコーディング | 入力からSQL・HTML・ファイル操作まで追い、認可条件を補う |
| [3](/blog/sc_3) | 認証・ID・証明書・鍵管理 | シーケンスの矢印に、値・検証者・検証条件を書き込む |
| [4](/blog/sc_4) | ネットワーク・メール・通信制御 | 通信を開始する主体、NAT後のアドレス、許可・観測位置を示す |
| [5](/blog/sc_5) | インシデント対応 | 記録を根拠にタイムラインを作り、封じ込めと追加調査を選ぶ |
| [6](/blog/sc_6) | 開発・脆弱性管理・委託・BCP | 仕様に合う診断と対処、業務に必要な復旧準備を説明する |
| [7](/blog/sc_7) | 暗号・クラウド・法務・基礎 | メモリ・DB・OSの弱点も補い、科目Aで不足する範囲を把握する |
| [8](/blog/sc_8) | 独自演習・答案改善・全実問対応 | 根拠と答案の要素を対応させ、指定時間で2問を完答する |

用語表の **Aは記述まで仕上げる基礎、Bは構成・仕様に適用する知識、Cは追加の補強** を示す編集上の目安。実際の出題頻度、得点配分、出題の有無を意味しない。Cの項目が実問の中心になる場合もある。

学習時間を固定の分野別パーセントに割り振るより、まず各章から1題ずつ解き、失点の原因を見て配分する。Web・認証・ネットワーク・調査・管理のうち一つしか解けない状態では、4問から2問を選ぶ余地が小さい。

## 4. 過去問を一周して終わらせない

| 段階 | 作業 | 残すもの |
|---|---|---|
| 初回 | 解答例を見ずに書く。根拠となる図・行・表の条件を示す | 自分の答案、所要時間、根拠 |
| 照合 | 問題・公式解答・講評を往復する | 欠けた主語・条件・対象と誤読した箇所 |
| 補強 | 対応する本書の節を読み、自分の言葉で理由を説明する | 成立条件と、それを断つ対策の一組 |
| 再演習 | 解答を閉じ、後日もう一度書く | 前回の誤りを直せたか |
| 通し演習 | 統合後の一回分を150分で解く | 選んだ理由、完答状況、見直し時間 |

**誤答ノートの書式**：「実問／自分の答案／根拠／不足要素／修正答案／再演習日」。正解文を写すだけでは、別の構成の問題に応用できない。

科目A-2は旧午前Ⅱの25問単位、科目A-1の免除がない場合は旧午前Ⅰの30問単位でも取り組む。本書は科目Bを中心とし、午前Ⅰの経営・会計・アルゴリズム等をすべて解説する総合教科書ではない。補強範囲は[第7章](/blog/sc_7)で確認する。

## 5. 問題選択と記述の判断

最初の約10分で4問の設問と主要な図表を確認し、次を比べる。この時間は練習用の目安である。

1. **根拠を拾えるか**：知っている単語の数より、図表・コードと設問を対応させられるか。
2. **答えられる範囲が広いか**：冒頭の一問だけで判断せず、後半の設計・調査・運用も確認する。
3. **要求が具体的か**：行番号・設定値・手順を答えられる見込みがあるか。
4. **時間内に書き切れるか**：読解・作表・記述に掛かる時間を見積もる。

解けない小問は印を付けて進み、残りの根拠から戻る。問題を変える場合は、既に使った時間と残りの完答見込みを比べる。選択分野を先に固定しすぎない。

答案は **「誰が／何を／どこで／どの条件で／どうする」** のうち、問いが要求する要素を残す。「セキュリティを強化する」「ログを確認する」「MFAを入れる」といった一般論で止めない。具体例と自己点検は[第8章](/blog/sc_8)へ進む。
